# 可逆派車情境模擬

這個功能只存在於 `feature/dispatch-simulation` 分支；穩定版 `main` 沒有被修改。

## 如何使用與復原

- 預設為關閉，不會影響原本 Demo。
- 在「行動清單」按「開始模擬」，選擇假設 30 分鐘內能處理路線前幾站。
- 按「揭曉 30 分鐘後結果」後，系統才會利用原始歷史真值估算潛在改善上限。
- 按「關閉並重設」即可退出；歷史揭曉結果不會被清除或改寫。
- 若要完全回到未加入此功能的程式版本，執行 `git switch main`。

## 計算方式

1. 先依既有 `route_order` 取得路線前 K 站，不能在看過答案後自行挑站。
2. 揭曉 API 仍評估完整行動清單，原始 Precision 不會因 K 改變。
3. 前 K 站中，只有歷史上在 30 分鐘後仍缺車／仍滿柱的站，才計為「可能改善」。
4. 歷史上自行恢復的站不算模擬改善。
5. 顯示的剩餘持續失衡上限為：`原始命中站數 - 可能改善站數`。

## 邊界與假設

這是前端記憶體中的單步情境推估，不會寫入後端、模型、S3、歷史資料或下一時點特徵。它假設調度能在 30 分鐘內準時抵達，而且處理後至少維持到目標快照。由於題目資料沒有車程、車輛載量、實際派車紀錄與介入後借還需求，因此結果只能稱為「潛在改善上限」，不能稱為真實派車成效。

模擬結果不得接續成 t+60 或 t+90 的模型輸入，避免改寫歷史資料後產生不可靠的連鎖預測。

## 地圖語意

- 揭曉前：青色路線是原模型建議，藍色虛線圈是納入模擬的前 K 站。
- 揭曉後：灰線保留原預測建議；紅線只連接事後確認仍失衡的行動站。
- 紅線是事後解說，不是決策當下可知的派車路線。
- 站點紅／綠色仍只代表歷史真值，模擬不會把站點改色。
